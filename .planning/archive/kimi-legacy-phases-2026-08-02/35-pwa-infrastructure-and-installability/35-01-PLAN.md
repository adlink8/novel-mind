# Phase 35-01 Plan: Manifest + 图标 + 可安装性验证

## Steps

1. **写 manifest 元数据路由**：在 `frontend/src/app/manifest.ts` 导出 `MetadataRoute.Manifest`，字段：`name`、`short_name`、`description`、`start_url: "/"`、`display: "standalone"`、`background_color`、`theme_color`（与现有 globals.css 主题色对齐）、`icons[]`（含 `purpose: "any maskable"`）。
2. **准备图标集**放 `frontend/public/icons/`：`icon-192.png`、`icon-512.png`、`maskable-512.png`（用现有 logo 生成；若无 logo，用占位生成器产出符合尺寸的 PNG，后续 Phase 39 收口时替换正式品牌图标）。
3. **挂载到 layout**：在 `frontend/src/app/layout.tsx` 的 `metadata` 加 `manifest: "/manifest.webmanifest"`、`appleWebApp: { capable: true, statusBarStyle: "default", title: "NovelMind" }`、`icons` 中加 `apple-touch-icon`，viewport meta 保持现有响应式设置。
4. **构建验证**：`env -u NODE_OPTIONS npm run build` 通过；DevTools > Application > Manifest 无报错、图标正确解析。
5. **可安装性验证**：`npm start -- -p 3010`（`BACKEND_URL=http://127.0.0.1:8000`）后跑 Lighthouse PWA audit，确认 `installable: true`。

## Must-Haves

- manifest 所有字段完整，引用的图标文件实际存在于 `public/`。
- `display: "standalone"`（启动无浏览器地址栏）。
- iOS 兼容：`apple-touch-icon` + `apple-mobile-web-app-capable` meta 就位（iOS 不完全支持 manifest，需兼容 meta）。
- 构建不回归：`env -u NODE_OPTIONS npm run build` 成功，现有 vitest 套件不红。
- 不引入运行时网络依赖（图标为本地静态资源，不外链）。

## Verification

- `env -u NODE_OPTIONS npm run build` 成功产出 `.next/`，无 manifest 相关报错。
- Lighthouse PWA audit：`installable = true`，无 manifest 错误项。
- DevTools > Application > Manifest 面板显示 name/icons/theme，无警告三角。
- 手机 Safari「添加到主屏幕」出现自定义图标与名称（手动或 BrowserStack 验证，留证据截图）。
- `npm run test`（vitest）全绿，无回归。
