# Phase 35-02 Plan: @serwist/next 集成 + app-shell cache-first SW

## Steps

1. **装依赖**：在 frontend 装 `@serwist/next` 与 `serwist`（隔离到 frontend 本地 node_modules；若沙箱死代理影响，用 `env -u HTTPS_PROXY -u HTTP_PROXY` 绕开，沿用项目既有装包约定）。
2. **写 Service Worker 源**：新建 `frontend/src/app/sw.ts`，实例化 `Serwist`，注册路由：
   - app-shell / 静态资源（`/_next/static/`、HTML、JS、CSS、字体）→ `CacheFirst`（或 `StaleWhileRevalidate`），设 cache 名 `novelmind-shell-v1`。
   - `/api/*` GET → `NetworkFirst`，超时 ~3s 回退缓存，cache 名 `novelmind-api-v1`。
   - 非 GET（POST/PUT/DELETE）→ 不缓存（直通网络）。
   - `skipWaiting: true` + `clientsClaim: true`；设 cache 上限避免无限增长。
3. **包裹 next.config**：在 `frontend/next.config` 用 `withSerwist` 包裹现有配置，指定 `swSrc: "src/app/sw.ts"`、`swDest: "public/sw.js"`、`disable: process.env.NODE_ENV === "development"`（dev 不挂 SW，避免缓存干扰 HMR）。
4. **构建与启动验证**：`env -u NODE_OPTIONS npm run build` 通过（产出 `public/sw.js`）；`npm start -- -p 3010` + `BACKEND_URL=http://127.0.0.1:8000`，确认 SW 注册成功、预缓存清单生成。

## Must-Haves

- SW 仅在生产构建启用，dev 必须禁用（否则缓存污染 HMR 调试）。
- app-shell 资源 cache-first，离线秒开。
- `/api/*` network-first，在线走网络、离线回退缓存（不抛错，不白屏）。
- 非 GET 请求与 POST 写操作不缓存（避免脏写/鉴权缓存）。
- cache 设条目/大小上限，避免无限膨胀。
- 后端零改动：仅改 `frontend/next.config` + 新增 `frontend/src/app/sw.ts`；`backend/` 无 diff。
