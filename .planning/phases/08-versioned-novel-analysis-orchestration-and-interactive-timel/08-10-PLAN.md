## Must-Haves

- `verify_release_evidence_from_db()` has a repository call site reachable from a documented CLI mode and exercised by CI.
- Positive evidence is produced, not supplied: the gate opens its own DB sessions and computes command output digests from subprocess bytes.
- No positive test uses synthetic authority, copied report authority, fixed pseudo-digests, monkeypatched successful results, or `'f' * 64`.
- The low-level pure verifier may remain injectable for negative unit contracts, but it is not the production release entrypoint.
- Failed commands, missing rows, changed authority rows, malformed reports, and DB/report disagreement all return a non-zero/blocked release result.
- Deferred relationship graph, reader AI, clue tracking, history support, and unrelated user changes remain untouched.

## Trust Boundaries

| Boundary | Description |
|---|---|
| qualification report → release CLI | Report content and claimed hashes/authority are untrusted until independently checked. |
| release CLI → subprocesses | Command execution must use fixed structured specs and capture real output without shell injection. |
| release CLI → PostgreSQL | The gate must establish its own session and re-read persisted authority after report creation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-08-10-01 | Spoofing | report authority | mitigate | Ignore caller observations; resolve report references through `verify_release_evidence_from_db()` and an internally imported session factory. |
| T-08-10-02 | Tampering | command attestations | mitigate | Execute fixed argv/cwd specs and hash captured output bytes inside the gate; reject non-zero exits and missing/duplicate commands. |
| T-08-10-03 | Repudiation | release verdict | mitigate | Emit command, exit code, output digest, per-check verdict, and final status as machine-readable evidence without exposing sensitive output. |
| T-08-10-04 | Elevation of Privilege | command runner | mitigate | Do not accept arbitrary commands or shell fragments from report/CLI input; production command list is code-owned. |
| T-08-10-SC | Tampering | package supply chain | mitigate | No package installs or dependency changes are permitted by this plan; existing lockfiles and CI service lock remain authoritative. |
