# 20-01 NM read-only structure API

## Objective

Expose Narrative Memory **candidate** structure for the analysis Structure Workspace: list versions, tree, node claims, source links — without promotion or builder mutation.

## Steps

### Task 1: Pydantic product schemas
- File: `backend/app/schemas/narrative_memory_product.py`
- Models (names flexible, fields required):
  - `NmVersionListItem`: version_id, version_key, readiness (`empty`|`incomplete`|`preview_eligible`|`sealed_candidate`), node_counts optional, badge fixed `candidate_preview`
  - `NmStructureNode`: id, node_key, node_kind, display_label, chapter_start, chapter_end, child_ids
  - `NmStructureTreeResponse`: novel_id, version_id, through_chapter, publication_status=`candidate_preview`, readiness, nodes[], message?
  - `NmClaimItem`: id, claim_kind, summary/text fields from typed payload, uncertainty, confidence, visible_from_chapter, node_id
  - `NmSourceLinkItem`: claim_id, evidence identifiers + chapter_number + offsets/hash when present
- **Never** include fields that imply production active promotion

### Task 2: structure_query service
- File: `backend/app/services/narrative_memory/structure_query.py`
- `list_versions(db, owner_id, novel_id)` — SQL on `NarrativeMemoryVersion` + optional build report/manifest for readiness; no default pick
- `load_structure_tree(db, owner_id, novel_id, version_id, through_chapter)`:
  - Verify version belongs to owner/novel
  - Load nodes where `chapter_end <= through_chapter` (and chapter_start visible)
  - Load `contains` edges among visible nodes; build child_ids
  - Order: prefer global → arcs → chapter_state for display hints via kind
  - Set `publication_status=candidate_preview` always
  - If version missing → 404-equivalent error; if no nodes → empty nodes + readiness incomplete/empty
- `load_node_claims(...)` and `load_node_source_links(...)` with `visible_from_chapter <= through_chapter`
- Prefer reusing helpers from `candidate_reader` where safe; if `load_eligible_version` is too strict for incomplete builds, implement owner-scoped **preview** path that still never writes and still filters cutoff
- **No writes**, no promote, no builder start

### Task 3: FastAPI router
- File: `backend/app/api/narrative_memory.py`
- Auth: `require_user` + `require_owned_novel` (same as clues)
- Routes:
  - `GET /api/narrative-memory/{novel_id}/versions`
  - `GET /api/narrative-memory/{novel_id}/versions/{version_id}/tree?through_chapter=`
  - `GET /api/narrative-memory/{novel_id}/versions/{version_id}/nodes/{node_id}/claims?through_chapter=`
  - `GET /api/narrative-memory/{novel_id}/versions/{version_id}/nodes/{node_id}/source-links?through_chapter=`
- Register in `main.py` with tags e.g. `叙事记忆结构`
- through_chapter: required or default high; if novel max chapter known, clamp; reject nonsense

### Task 4: Unit tests
- File: `backend/tests/unit/narrative_memory/test_structure_query.py` (and/or API test with mocks)
- Cases:
  1. No versions → empty list
  2. Version with nodes beyond cutoff → filtered out of tree
  3. Response always `candidate_preview`
  4. Claims filtered by visible_from_chapter
  5. Foreign owner/version → not found
- **Test, Fix, and Confirm**

## Must-Haves

- Explicit version_id only
- through_chapter enforced server-side
- candidate_preview always
- Zero write paths in this router/service
