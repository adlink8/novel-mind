## Must-Haves

- LLM 只分类边界，不生成正文、不写库、不调用工具、不决定发布。
- provider schema 不能替代本地 strict schema 与业务校验。
- 每个失败都有确定性 fallback 和 lineage；fallback 不标记 qualified。

## Failure Modes

- provider 声称 structured output 但返回非法 JSON：本地拒绝，最多一次修复重试后 fallback。
- 模型 alias 无 revision：允许 fallback candidate，但标记不可作为新模型 baseline。
- budget/cost 缺失：按 token/resource budget fail closed，不把缺失记为零成本成功。

## Outputs

- strict boundary contracts、bounded adjudicator、budget ledger、fallback audit 与 adversarial tests。
