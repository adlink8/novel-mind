## 关键设计

- **allowlist 校验在构造 adapter 之前**（T-25.3-03-01）：http 必须 https，拒绝 loopback/private/
  link-local（127/8、10/8、172.16/12、192.168/16、169.254/16、localhost、::1、fc00::/7、fe80::/10、
  0.0.0.0）与内部端口（5432/8000/8010）；stdio 必须绝对路径，禁止 psql/pg_dump/sqlite3/mysql/
  shell（bash/sh/zsh/fish/cmd/powershell/pwsh）/包运行器（npx/npm/yarn/pnpm/bun）/python 解释器，
  参数禁止浮动包引用（@latest/@*）。每条拒绝消息均 `McpAllowlistError` 指名服务器+规则。
- **无 DB env 泄漏面**：validateMcpAllowlist 拒绝任何携带 `env` 属性的服务器条目；buildMcpConfig
  不注入 env；测试断言构建配置 JSON 无 postgres/database_url。
- **proxy-only 表面**：settings.directTools=false 恒置，无服务器级 directTools/includeTools/excludeTools；
  hostConfigDiscovery "off"、autoAuth false、lifecycle "lazy"、requestTimeoutMs 30_000、exposeResources false。
- **D-09 信封**：`toExternalEvidence(serverName, toolName, result, opts)` 产出
  `{type, schema_version:1, sources[{server,tool,uri,title,retrieved_from:"mcp"}], retrieval_time,
  claims[{text,source_index}], confidence, prohibited_from_canon:true, release_status:"external"}`；
  uri/title 可从结果首项元数据提取；`prohibited_from_canon` 是字面量常量，无参数可翻转。
- **后端双层防线**：schema 层 `prohibited_from_canon: Literal[True] = True`（wire 无法断言 false，
  省略仍持久化 true）；服务层 artifacts 门禁 external_evidence 仅 rejected 分支（永不发布）。
- **finalizer 边界**（沿用 25.2-03）：`validate_answer_against_manifest` 只认识
  original_text_evidence 白名单，mcp:// 引用按构造失败；稳定错误码 failed_validation。

## Pitfall 7 决策（TS-source 加载机制）

pi-mcp-adapter 的 exports 直接指向 `.ts` 源码，包内 import 带 `.ts` 扩展名；直接 `import "pi-mcp-adapter"`
会把整包源码拉进 `tsc --noEmit` 程序并触发 TS5097。**决策**：`tsconfig.json` `paths` 把
`pi-mcp-adapter` 映射到 `src/mcp/pi-mcp-adapter.shims.d.ts`（类型层，ambient module 声明仅覆盖
spike 消费的 API 表面）；运行时由 vitest/Node 解析真实包，单元测试以 `vi.mock("pi-mcp-adapter")`
隔离真实包。真实包 live-run 留给 Task 3。
