## Pattern Assignments

### `agent-service/packages.lock.json` (config — D-04 governance lock manifest)

**Analog:** `frontend/package-lock.json` — field conventions only (`version`, `resolved`, `integrity` per entry); the governance fields (verdict, permission_manifest, qualification_report) are new and defined by RESEARCH Pattern 1.

- npm's `package-lock.json` remains the CI lockfile; `packages.lock.json` never replaces it — it adds verdict/provenance/permission metadata keyed by `name@version` with matching `integrity`.
- Exact pins only — mirrors the house convention from 25.2-PATTERNS (`frontend/package.json`: `"vitest": "4.1.10"`, no floating ranges).

### `agent-service/src/governance/*.ts` (service, file-I/O/transform — D-05/D-06 startup chain)

**Analog:** 25.2-05 `src/skills/loader.ts` contract (`25.2-05-PLAN.md` Task 3) — the fail-closed loader pattern this phase extends:

- ajv meta-schema validation, **fail closed naming the offending field** (loader behavior block, verbatim from the plan):
  > "skill.yaml missing any D-09 required field → load fails closed naming the field; allowed_tools containing a name outside DOMAIN_TOOL_NAMES → load fails closed naming the tool; input.schema.json / output.schema.json that are not valid JSON Schema → load fails closed"
- Deps already pinned there: `yaml`, `ajv`, `ajv-formats` — exact pins, no `^` (acceptance criterion: "agent-service/package.json contains exact pins for yaml, ajv, ajv-formats"). **Reuse these; do not add a second validation library.**
- Startup sequencing: the governance chain runs before `server.listen` — same position the 25.2-05 loader occupies (skills load before any session creation).

**`tool-registry-manifest.ts` single-source pattern** (from 25.2-05 Task 1): `buildDomainTools` exports `DOMAIN_TOOL_NAMES` as "the allowlist `tools` array the session factory and skill loader both consume — single source", with a test asserting deep-equality "so the registry, session allowlist, and skill validation cannot drift". The manifest becomes the new single source; keep the drift-guard test.

**Collision gate** (new code — RESEARCH Pattern 3 example): throw `ToolCollisionError` naming both `provider_package`s; process exits before listening. Anti-pattern avoided: silent load-order override (D-06).

No in-repo analog (first permission engine). Pattern source is RESEARCH Pattern 4 (clean-room, semantics from pi-permission-system's documented configuration model). Conventions to carry over from in-repo analogs:

- **Frozen constant table + mirror test** — from 25.2-05 `AGENT_TOOL_ERRORS` contract: "no agent-service-only codes invented" and "a test asserts the facade envelope code set equals AGENT_TOOL_ERRORS (single-source assertion, not a duplicated literal)". `DOMAIN_ACTION_POLICY` follows the same rule: one exported const, tests consume it, never re-literal it.

### Fail-closed loader/validator
**Source:** 25.2-05 `src/skills/loader.ts` contract + `tests/ci` static gates
**Apply to:** all of `src/governance/`, `scripts/*.mjs`
Fail closed naming the offending field/package/tool; exit≠0; no auto-fix, no prompt, no default-permissive fallback. Unknown → deny/block everywhere (manifests, policy actions, MCP allowlist).

### Frozen-table + single-source mirror test
**Source:** 25.2-05 `AGENT_TOOL_ERRORS` / `DOMAIN_TOOL_NAMES` contracts
**Apply to:** `DOMAIN_ACTION_POLICY`, `ToolRegistryManifest`, `packages.lock.json` schema
One exported const/manifest; tests assert against the source, never a duplicated literal; drift-guard test on every consumer pair.

### Cancel-without-write / approval-only mutation
**Source:** `backend/app/services/reader_chat/worker.py:316-346,401-409` + 25.2-03 artifacts gate
**Apply to:** `services/agent_runtime/approvals.py`, external_evidence persistence
Approval state mutates only via FastAPI service functions; a cancelled/rejected run writes nothing; the SSE frame notifies, the server decides.

### ORM / migration conventions
**Source:** `backend/app/models/base.py:20,36-60`; `reader_chat.py:32-96,273-285,427-431`; migrations `17_`/`24_`/`26_`
**Apply to:** `approval_requests` table + `27_approval_requests.py`
`JSONB` variant, `TimestampMixin`, denormalized `owner_id`, `ck_`/`uq_`/`idx_` naming, `String(64)` checksums, idempotent guards, head-test bumps in the same commit.
