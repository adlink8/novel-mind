# Phase 25.3-05 — pi-web-ui Renderer Feasibility Note

**Plan**: 25.3-05 · **Date**: 2026-08-02 · **Type**: feasibility (D-03 selective verdict)
**Cross-reference**: `agent-service/qualification/earendil-pi-web-ui.md` (25.3-01 PackageQualificationReport)

## VERDICT

Pattern-only feasibility is **CONFIRMED**. pi-web-ui 0.75.3 contributes renderer *designs* —
the `registerToolRenderer` / `registerMessageRenderer` type-keyed component registry, compact
tool-result cards, and the artifact panel layout — all of which transfer cleanly to a plain
React implementation inside the existing Analysis Chat. The package itself is **never
installed or imported** (D-03 selective verdict). The runtime keeps the single 0.83.0 SDK
line; Next.js stays the rendering authority and PostgreSQL the session authority. This note
is the auditable rejection record; `cited-answer-artifact.tsx` (Task 2) is the prototype that
proves the borrowed pattern.

## BORROWED PATTERNS

| pi-web-ui pattern | React port in this phase |
|---|---|
| `registerToolRenderer` / `registerMessageRenderer` registry shape — a type-keyed map resolving an artifact/tool-result type to its renderer component | `ARTIFACT_RENDERERS` record keyed by artifact type (`cited_answer`, `external_evidence`) + `resolveArtifactRenderer(type)` in `cited-answer-artifact.tsx`, with an explicit `UnknownArtifactFallback` |
| Compact tool-result cards (small footprint, read-mostly) | `CitedAnswerArtifactView` renders answer blocks as compact text paragraphs; `ExternalEvidenceView` renders the D-09 fields in a bordered card |
| Artifact panel layout (preview inside the chat surface) | The artifact preview area of the Analysis Chat resolves through the registry, keeping header/status/approval chrome from the 25.2-04 workspace |

Zero imports from `@earendil-works/pi-web-ui` — the registry is a plain React record.

## REJECTED PATTERNS

| Pattern | Why rejected (recorded) |
|---|---|
| **ChatPanel adoption** | pi-web-ui's ChatPanel owns its own session state machine, conflicting with the 25.2-04 Analysis workspace whose session/rendering authority is Next.js + the 25.2 agent runtime. |
| **IndexedDB session authority** | Browser-local IndexedDB stores would create a shadow session authority; session authority must stay with PostgreSQL (25.2 architecture). Rejected on 25.2 D-15 / architecture grounds. |
| **Browser-held provider keys** | pi-web-ui's custom providers hold key material (`ollama`, `@lmstudio/sdk`) in the browser. 25.2 D-15 forbids any provider key material outside FastAPI; the frontend only ever receives server-shaped data. |
| **mini-lit + Tailwind v4 component stack** | The repo is a React/Next stack with `ui/dialog.tsx` conventions; adopting mini-lit/web components would duplicate the component surface and clash with the house styling. |
| **0.75.3 dependency train** (`pdfjs-dist`, CDN-tarball `xlsx`, `jszip`, `ollama`, `@lmstudio/sdk`, `docx-preview`) | Heavy and partly unusual deps (CDN tarball, exact-pinned pdfjs-dist) reinforce not-installing; none are needed to borrow a registry shape. |
| **Version drift 0.75.3 vs SDK 0.83.0** (Pitfall 3) | pi-web-ui 0.75.3 expects `^0.75.3` pi-ai/pi-tui while the runtime pins the 0.83.0 SDK line — installing would duplicate/conflict SDK copies. |

## BOUNDARY

- **Prototype renders**: one `CitedAnswerArtifact` (answer blocks + one CitationChip per
  evidence ref, citation jump to source) inside the existing Analysis Chat, plus the
  `ExternalEvidenceArtifact` (25.3-03 schema) display discipline — a persistent
  "External evidence — prohibited from canon" label and **no** citation-jump affordance
  into novel text (D-08/D-09).
- **Stays authority**: Next.js rendering; PostgreSQL sessions; FastAPI approval/artifact
  status transitions (25.2-03 shape). The renderer consumes server data only — no
  IndexedDB, no provider keys.
- **Standing rule**: any future reconsideration of pi-web-ui re-enters through the Package
  Legitimacy Gate (D-02/D-04), never as a direct dependency. Enforced by the 25.3-01
  tests/ci gate that forbids `@earendil-works/pi-web-ui` in any package.json.
