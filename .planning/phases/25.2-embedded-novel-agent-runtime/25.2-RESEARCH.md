# Phase 25.2: Embedded Novel Agent Runtime - Research

**Researched:** 2026-08-01
**Domain:** Pi SDK embedding (Node.js agent service), FastAPI read-tool reuse, Skill/Artifact persistence, SSE streaming workspace
**Confidence:** HIGH (Pi SDK surface verified against official docs + npm; codebase mapped by direct exploration)

## Summary

The Pi SDK embeds cleanly as a standalone Node service: `createAgentSession()` from `@earendil-works/pi-coding-agent@0.83.0` gives session lifecycle, streaming events, custom tools, and full ResourceLoader control — every D-decision has a verified SDK mechanism (`noTools: "all"` for D-05, `defineTool` + `customTools` for D-06, ResourceLoader overrides for D-18, `createProvider`/`pi.registerProvider` with `openai-completions` for D-15, `session.abort()`/`continue()` for cancel/retry, `SessionManager` + the pi-agent-core `SessionStorage` interface for persistence). The one genuinely open SDK question is how to wire a custom (PostgreSQL) `SessionStorage` into `createAgentSession` — the file-based `SessionManager` is documented, the storage-backend injection point is not; that is a 25.2-01 spike item.

On the NovelMind side, the biggest finding is what does **not** exist: there is no OpenAI-compatible HTTP endpoint, no SSE/streaming anywhere in the stack (reader chat is POST 202 + job polling), and no service-to-service auth. D-15 therefore requires a thin new FastAPI gateway router (`POST /api/gateway/v1/chat/completions`) in front of the existing `AIService` LiteLLM wrapper — everything else (keys, routing, budgets, SSRF guard) is reused. All 7 first-batch tool areas already have production read APIs with server-side owner/spoiler enforcement; narrative memory is the exception to handle with care — it is candidate-only by ADR-0002 and must be labeled as such. Persistence conventions are strong and copyable (reader_chat 10-table pattern; Alembic head `24idxjournal1`). The frontend has zero streaming code today; the Agent Workspace plugs in as a third `"agent"` tab in `/analysis` with fetch-stream SSE (native `EventSource` cannot send the Bearer header).

**Primary recommendation:** Build `agent-service/` (Node 24, TypeScript) embedding `createAgentSession` with `noTools: "all"` + 7 custom HTTP tools calling existing FastAPI read routes with the user's JWT forwarded; add one thin FastAPI gateway router exposing `AIService` OpenAI-compatibly behind a shared gateway token; register it as a custom pi-ai provider; stream via SSE parsed with fetch+ReadableStream in a new `<AgentWorkspacePanel>` tab on `/analysis`.

## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Architecture and authority
- D-01: The agent is an orchestrator, never a fact source or database administrator.
  Deterministic code keeps: novel import/chapter parsing/raw offsets, DB transactions,
  idempotency and job state machines, owner permissions and spoiler boundaries, retrieval,
  indexing and evidence validation, citation legality and Manifest freezing, Canon /
  Interpretation / Derivative space isolation, versions, rollback, budget and cost, image
  assets and in-text anchors.
- D-02: Integration shape: `Next.js → (SSE / WebSocket) → Novel Agent Service (Node.js /
  Pi SDK) → (internal HTTP / Tool RPC) → FastAPI NovelMind Core → PostgreSQL / Chroma /
  Neo4j / Redis / Asset Store`.
- D-03: Agent Service owns: Agent Session, Skill Registry / Skill Loading, Tool
  registration, planning and tool selection, streaming events, cancel/retry/resume, user
  approval flow, artifact preview transport.
- D-04: FastAPI Core owns: all formal novel data and facts, raw/RAG/world-model queries,
  EvidenceRef / Manifest, formal writes and version state, illustration jobs and assets,
  Canon Fork and branch data.
- D-20: Does not replace the stable Reader Chat chain; the runtime reuses its evidence,
  budget, citation and session foundation.

#### Tools
- D-05: First version disables Pi default coding tools (bash, file editing, arbitrary
  command execution); only NovelMind custom domain tools are registered.
- D-06: First batch implements 7 read-only tools: `get_novel`, `get_chapter`,
  `search_novel_text`, `get_timeline`, `get_relationships`, `get_clues`,
  `get_narrative_memory`. The full target registry (later phases): plus `get_events`,
  `get_character_state`, `get_character_knowledge`, `get_clue_chain`, `get_world_rules`,
  `get_visual_bible`, `get_evidence_span`, `search_narrative_units`.
- D-07: Every tool is enforced server-side by FastAPI with: owner check, reading cutoff /
  spoiler boundary, query budget, timeout, output size limit, evidence lineage, stable
  error codes.
- D-08: High-impact write tools (`publish_illustration`, `attach_illustration_to_text`,
  `create_canon_fork`, `apply_canon_delta`, `publish_derivative_chapter`) require explicit
  approval and never modify Original Canon — deferred out of this phase (phase is
  read-only).

#### Skills and Artifacts
- D-09: A Skill is a directory `skills/<skill-name>/` with `SKILL.md`, `skill.yaml`,
  `input.schema.json`, `output.schema.json`, `examples/`, `tests/`. `skill.yaml` declares
  at minimum: `name`, `version`, `allowed_tools`, `read_permissions`,
  `write_permissions`, `forbidden_spaces`, `budget`, `approval_required_for`,
  `input_schema`, `output_schema`.
- D-10: Every completed agent step emits a structured Artifact carrying: artifact type /
  schema version, owner / novel / branch, producing skill + version, agent runtime +
  model lineage, source versions, input hash, evidence refs, status (`candidate` /
  `validated` / `approved` / `published` / `rejected`), parent artifact / revision.
- D-11: An agent session is never a long-term fact source; long-term state lives in the
  Domain DB and Artifact Store. Agent memory is replaceable; domain Artifacts, Canon and
  evidence chains must not depend on session memory.
- D-14: First official Skill: `answer-reading-question` with flow
  `Question → QueryPlan → Tool Calls → EvidenceRef materialization → Frozen Manifest →
  Cited Answer Artifact`.

#### Runtime and model routing
- D-12: "One agent per novel" is logical, not a resident process: a durable
  `NovelAgentProfile` (novel_id, agent_profile_version, enabled_skills,
  world_model_version, narrative_memory_version, visual_bible_version, reading_cutoff,
  active_derivative_branch, recent_artifacts) with short-lived sessions resumed per task.
- D-13: Single Novel Agent + multiple Skills + controlled Tools + deterministic Validator.
  No per-character/timeline/clue/illustration/reviewer sub-agents in v1.
- D-15: Model routing — formal direction is Pi calling the existing NovelMind Model
  Gateway / AI Router via a custom OpenAI-compatible provider (avoids dual
  key/routing/budget/price tables); direct Pi provider calls are acceptable inside the
  spike only.
- D-16: 25.2 uses only official Pi packages: `@earendil-works/pi-agent-core`,
  `@earendil-works/pi-ai` (or the gateway adapter), `@earendil-works/pi-coding-agent`
  SDK / ResourceLoader. No unmodified community packages (governance is Phase 25.3).
- D-17: `pi-storage-sqlite-node` is allowed only for spike session-restore validation;
  the formal service persists sessions through a NovelMind Storage Adapter on PostgreSQL.
- D-18: ResourceLoader is fully controlled: ambient global discovery disabled, default
  coding tools disabled, only project-allowlisted Skills/Extensions loaded.

#### Workspace
- D-19: `/analysis` Agent Workspace supports: streaming answers, current-phase and
  tool-call summaries, artifact preview, citation jump-to-source, cancel/retry, user
  approve/reject of candidate results, session restore.

#### Gating and non-goals
- D-21: Execution of this phase starts only after the Phase 22 three-consecutive-green
  scheduled gate closes (roadmap execution rule); planning artifacts may proceed now.
- D-22: Non-goals — no shell/file-editing/arbitrary-command tools; no Original Canon
  mutation; no multi-agent; no automatic illustration publication; no derivative text
  publication.

### Pattern 1: Disable coding tools, register only domain tools (D-05/REQ-AGENT-01)
**What:** `noTools: "all"` plus explicit custom tool allowlist; belt-and-braces `beforeToolCall` gate.
**When to use:** every agent session creation.
**Example:**
```typescript
// Source: https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/sdk.md (Tools section)
import { createAgentSession, defineTool } from "@earendil-works/pi-coding-agent";
import { Type } from "typebox";

const getChapter = defineTool({
  name: "get_chapter",
  label: "Get Chapter",
  description: "Read a chapter of the current novel (owner- and spoiler-enforced server-side)",
  parameters: Type.Object({
    chapter_id: Type.Number({ description: "Chapter id" }),
  }),
  execute: async (_id, params, signal) => fastapiToolCall("get_chapter", params, signal),
});

const { session } = await createAgentSession({
  noTools: "all",                      // kills read/bash/edit/write/grep/find/ls
  customTools: [/* the 7 tools */],
  tools: ["get_novel", "get_chapter", "search_novel_text", "get_timeline",
          "get_relationships", "get_clues", "get_narrative_memory"],
  resourceLoader: allowlistedLoader,   // Pattern 3
  modelRuntime,
});
```

### Pattern 2: NovelMind gateway as a Pi provider (D-15)
**What:** register the FastAPI gateway as a custom `openai-completions` provider; Pi never sees provider keys.
**When to use:** formal service (spike may use direct providers, D-15).
**Example:**
```typescript
// Source: https://raw.githubusercontent.com/earendil-works/pi/main/packages/ai/README.md (Custom Providers)
import { createModels, createProvider, type Model } from "@earendil-works/pi-ai";
import { openAICompletionsApi } from "@earendil-works/pi-ai/api/openai-completions.lazy";

const gatewayModel: Model<"openai-completions"> = {
  id: "reader-chat-default",          // logical name; FastAPI maps to real deployment
  name: "NovelMind Gateway",
  api: "openai-completions",
  provider: "novelmind",
  baseUrl: `${process.env.FASTAPI_BASE_URL}/api/gateway/v1`,
  reasoning: false, input: ["text"],
  cost: { input: 0, output: 0, cacheRead: 0, cacheWrite: 0 }, // cost authority stays in FastAPI
  contextWindow: 128_000, maxTokens: 4_096,
};

const models = createModels();
models.setProvider(createProvider({
  id: "novelmind",
  name: "NovelMind Gateway",
  baseUrl: gatewayModel.baseUrl,
  auth: { apiKey: { name: "Gateway token", resolve: async () => ({ auth: { apiKey: process.env.GATEWAY_TOKEN } }) } },
  models: [gatewayModel],
  api: openAICompletionsApi(),
}));
```
Equivalent extension-style alternative also verified: `pi.registerProvider("novelmind", { baseUrl, apiKey: "$NOVELMIND_GATEWAY_TOKEN", api: "openai-completions", models: [...] })` (extensions.md, async factory example).

### Pattern 3: Fully controlled ResourceLoader (D-18)
**What:** override every discovery surface; nothing ambient loads.
**Example:**
```typescript
// Source: sdk.md (ResourceLoader / Skills / Context Files sections)
import { DefaultResourceLoader } from "@earendil-works/pi-coding-agent";

const loader = new DefaultResourceLoader({
  systemPromptOverride: () => NOVEL_AGENT_SYSTEM_PROMPT,
  skillsOverride: () => ({ skills: allowlistedSkills, diagnostics: [] }),   // from SkillRegistry only
  agentsFilesOverride: () => ({ agentsFiles: [] }),                          // no ambient AGENTS.md
  extensionFactories: [novelmindGuardExtension],                             // inline, named; no disk discovery
});
await loader.reload();
```
Caveat: `DefaultResourceLoader` still uses `cwd`/`agentDir` for discovery of `.pi/` and `~/.agents/` unless every override replaces the discovered set — the spike must verify the override list is exhaustive (skills/prompts/themes/extensions/context files). If any surface cannot be overridden, point `agentDir` at an empty controlled directory.

### Pattern 4: Pi `SessionStorage` on PostgreSQL (D-17 formal)
**What:** implement the pi-agent-core storage contract against FastAPI-persisted tables.
**Example (verified interface surface):**
```typescript
// Source: https://cdn.jsdelivr.net/npm/@earendil-works/pi-storage-sqlite-node@0.83.0/dist/sqlite/storage/index.d.ts
// SessionStorage (from @earendil-works/pi-agent-core) requires:
//   getMetadata, getLeafId, setLeafId, createEntryId, appendEntry(SessionTreeEntry),
//   getEntry, findEntries(type), getLabel, getSessionName, getSessionStats,
//   getPathToRootOrCompaction, getEntries(cursor), cleanup
// Repo-level contract (create/open/list/delete/fork) mirrors SqliteSessionRepoApi.
```
The sqlite backend stores the same JSONL tree entries (id/parentId) the file `SessionManager` writes — so the PG adapter can persist one row per session entry (`agent_session_entries`) with `(session_id, entry_id)` uniqueness. **Open question (spike 25.2-01):** how `createAgentSession` accepts a custom `SessionStorage` — `SessionManager` factories documented in sdk.md are file/in-memory only; the injection seam (services object or subclass) must be discovered in the spike. Fallback: keep Pi sessions in-memory per run and persist NovelMind-owned run/message state in `skill_runs` + artifacts (D-11 makes session memory replaceable anyway).

### Pattern 5: SSE streaming of Pi events (D-19)
**What:** subscribe once per run; serialize a curated event subset as SSE `data:` frames.

### Anti-Patterns to Avoid
- **Enforcing anything in the system prompt:** D-07 requires server-side enforcement. The prompt may describe tools; it must never be the only guard (owner/spoiler/budget live in FastAPI).
- **Letting Pi load skills on demand:** Pi's skill mechanism loads SKILL.md content through the `read` tool — which D-05 disables. Skill instructions must be injected by the agent-service (system prompt / `before_agent_start` message) from the SkillRegistry, not discovered by the model.
- **Writing artifacts from the agent loop directly:** artifacts are written only at run finalization by deterministic service code (cancel-without-write, CONTEXT specifics).
- **Two sources of model cost:** Pi-side `cost` metadata must stay zeroed; cost authority remains FastAPI price snapshots (reader-chat pattern), otherwise budgets diverge (D-15 rationale).
- **Treating NM tool output as fact:** `get_narrative_memory` returns candidate-only data (ADR-0002); the tool response envelope must carry `release_status: "candidate"` labeling.
- **`window.confirm` / native `EventSource`:** repo has proper `ui/dialog.tsx`; EventSource can't carry the Bearer header — use fetch-stream.

## Common Pitfalls

### Pitfall 1: Assuming an OpenAI-compatible endpoint already exists
**What goes wrong:** planner points Pi at `http://backend/v1` and gets 404.
**Why it happens:** the "Model Gateway" is in-process LiteLLM (`ai_service.py`), not an HTTP service.
**How to avoid:** 25.2-02 (or late 25.2-01) includes the thin `backend/app/api/gateway.py` router; register in `main.py` next to existing routers.
**Warning signs:** provider stream errors with HTML error bodies.

### Pitfall 2: `SessionManager` is file-based — PG adapter seam is undocumented
**What goes wrong:** plan assumes `SessionManager.postgres()` exists; it does not.
**Why it happens:** sdk.md documents file/in-memory factories only; the `SessionStorage` interface lives in pi-agent-core, one package down.
**How to avoid:** spike experiment "wire custom SessionStorage into createAgentSession" with an explicit fallback (in-memory Pi session + NovelMind-owned run state). Timebox it; the fallback satisfies D-11/D-12 regardless.
**Warning signs:** type errors passing a custom storage object; session restore only works via JSONL files.

### Pitfall 3: Skills silently not loading because `read` is disabled
**What goes wrong:** agent never follows skill instructions; outputs drift.
**Why it happens:** Pi progressive disclosure loads SKILL.md through the `read` tool; `noTools: "all"` removes it.
**How to avoid:** inject skill instructions deterministically (system prompt per skill run); treat Pi's skill discovery as metadata-only.
**Warning signs:** skill runs whose traces show no skill-specific behavior.

### Pitfall 4: Streaming mismatch — repo has zero SSE today
**What goes wrong:** frontend assumes EventSource; auth header silently dropped; CORS/cookie failures.
**Why it happens:** all current chat is POST 202 + 700 ms polling.
**How to avoid:** fetch-stream helper with the same Bearer token source as the axios interceptor; Playwright 390px + desktop coverage of stream/abort.
**Warning signs:** 401 on stream open; events arriving only at completion.

### Pitfall 5: Alembic head assertions break in existing tests
**What goes wrong:** `test_postgres_migrations.py` (`EXPECTED_HEAD = "24idxjournal1"`) and `tests/integration/reader_chat/test_migration.py` (asserts `"18appsetting1"` in `alembic current`) go red when the new migration lands.
**Why it happens:** head is a hardcoded constant in two places.
**How to avoid:** 25.2-03 bumps `EXPECTED_HEAD` to `26agentrun01` and updates the reader_chat assertion in the same commit.
**Warning signs:** integration suite red immediately after migration commit.

### Pitfall 6: Windows dev environment friction
**What goes wrong:** DB/Chroma unavailable; paths with GBK/console issues; Node native deps.
**Why it happens:** Docker Desktop 29.6.1 is installed but the daemon was **not running** at research time (npipe error); `pg_isready`/`redis-cli` not on PATH; backend migrations README documents a Windows GBK caveat; worktree path contains no spaces but shells differ (Git Bash vs PowerShell).
**How to avoid:** plan's dev-orchestration step starts Docker Desktop / `docker compose up -d db chroma` first; agent-service itself is plain Node (no docker, no native builds — `node:sqlite` used by the spike package is a Node 24 builtin); document the three-process dev flow (uvicorn :8000, next :3000, agent-service :3100) in README after verification.
**Warning signs:** ECONNREFUSED 5432/8001; alembic Unicode errors on GBK consoles.

### Pitfall 7: Agent becomes a shadow fact source (D-01 violation)
**What goes wrong:** later phases read agent session transcripts or NM tool outputs as facts; citations not re-verified.
**Why it happens:** convenient to consume what's already in the session.
**How to avoid:** artifacts are the only output channel; every citation re-verified server-side against a frozen manifest (reuse `validate_answer_against_manifest` pattern); `NovelAgentProfile` stores version references, never content; NM tool envelope labeled `candidate`.
**Warning signs:** code reading `agent_sessions` outside the agent-service; artifacts without `evidence_refs`.

### Custom domain tool with timeout + stable error envelope (D-07)
```typescript
// Pattern: tool facade (agent-service). Enforcement stays in FastAPI; facade adds
// timeout, byte cap, and error-code normalization (Node-side gaps found in research).
import { defineTool } from "@earendil-works/pi-coding-agent";
import { Type } from "typebox";

export const AGENT_TOOL_ERRORS = {
  FORBIDDEN: "forbidden", BEYOND_CUTOFF: "beyond_cutoff", BUDGET_EXCEEDED: "budget_exceeded",
  TIMEOUT: "timeout", TOO_LARGE: "output_too_large", UPSTREAM: "upstream_error",
} as const; // stable once published — freeze in 25.2-02

async function fastapiToolCall(name: string, params: unknown, signal: AbortSignal, auth: string) {
  const ctrl = AbortSignal.any([signal, AbortSignal.timeout(30_000)]); // per-tool hard timeout
  const res = await fetch(`${process.env.FASTAPI_BASE_URL}/api/agent-tools/${name}`, {
    method: "POST",
    headers: { "content-type": "application/json", authorization: auth },
    body: JSON.stringify(params),
    signal: ctrl,
  });
  const text = await res.text();
  if (text.length > 64 * 1024) throw new Error(AGENT_TOOL_ERRORS.TOO_LARGE); // byte cap
  if (!res.ok) throw new Error(mapFastapiError(res.status, text));           // stable codes
  return { content: [{ type: "text" as const, text }], details: {} };
}

export const getTimeline = defineTool({
  name: "get_timeline",
  label: "Get Timeline",
  description: "Timeline events for the current novel, spoiler-cutoff enforced server-side",
  parameters: Type.Object({
    full_book: Type.Optional(Type.Boolean({ description: "Only honored if the user's persisted full-book switch is on" })),
  }),
  execute: async (id, params, signal) => fastapiToolCall("get_timeline", params, signal, currentAuth()),
});
```

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
