## 四、关键实现决策

1. **工具 `tools` allowlist 永不缺席**：FINDINGS #1（`noTools:"all"` 使 allowedToolNames=[] 为 truthy，customTools 必须显式列进 `tools`）→ `createSession` 用 `DOMAIN_TOOL_NAMES.filter(allowed_tools)` 构造非空数组；空 allowed_tools 或逃逸工具 → 会话创建前抛错（三重门：loader / registry / factory）。
2. **per-run 内部令牌流转**：server 解析 active 技能版本 → FastAPI 202 run-create（唯一授权）→ `internal_token` 作为工具门面 auth（测试断言 `Bearer tok-42` 而非端用户 JWT）；端用户 JWT 只用于 /api/agent 管理端点。
3. **断开检测**：`req.on("close")` + `res.on("close")` 双挂（Node 探针实测 `res:close` 最先触发），标志位去重；客户端断开即 `session.abort()` + 后端 cancel（cancel-no-write 跨服务边界）。
4. **SSE 握手**：`writeHead` 后必须 `res.flushHeaders()`，否则客户端 fetch 会因响应头未 flush 而挂起（实测修复）。
5. **finalize 端点（已补齐）**：25.2-05-PLAN 假设 25.2-03 提供 finalize HTTP 端点，初版缺失（service 函数有、路由无）。**已在 25.2-05 收尾时补齐**：`backend/app/api/agent.py` 新增 `POST /api/agent/novels/{novel_id}/skill-runs/{run_id}/finalize`（`SkillRunFinalize` schema：stop_reason/envelope/model_lineage/source_versions/usage/frozen_manifest；用当前请求 db 的 async engine 构造 sessionmaker，避免 DB 错位）；新增 2 个集成测试（happy path 写候选产物 / cancel-no-write 零写入），integration 15/15 通过。agent-service 调用路径与测试 mock 一致。cancel 端点 `POST .../skill-runs/{run_id}/cancel` 确认存在。
6. **依赖安装记录**（T-25.2-SC）：安装前 `npm view` 确认——`yaml 2.9.0`、`ajv 8.20.0`、`ajv-formats 3.0.1`（peer `ajv ^8` 兼容）；`npm install --save-exact` 精确 pin，无 `^`。

## 五、Handoff to 25.2-04（SSE 端点契约 / run API 形状）

### `POST /agent/novels/{novel_id}/runs`

请求（`content-type: application/json`，`authorization: Bearer <user JWT>` 必需，否则 401）：
```json
{ "question": "阿宁在竹林里看见了谁？", "skill": "answer-reading-question", "input": {}, "branch": null }
```
- `input` 与 `{novel_id, question}` 合并后经 skill input.schema 校验，失败 → 422（零会话创建）。
- run 授权只由 FastAPI `POST /api/agent/novels/{novel_id}/skill-runs` 202 完成（owner 检查 + per-run 内部令牌）。

响应：`text/event-stream`、`cache-control: no-cache`。帧（`data: {...}\n\n`）顺序契约：
| 帧 | 形状 | 来源 |
|---|---|---|
| `delta` | `{type:"delta", text}` | Pi `message_update`（text_delta/thinking_delta） |
| `tool_start` | `{type:"tool_start", toolName, args}` | Pi `tool_execution_start` |
| `tool_end` | `{type:"tool_end", toolName, isError}` | Pi `tool_execution_end` |
| `turn_end` | `{type:"turn_end", usage}` | Pi `turn_end` |
| `artifact` | `{type:"artifact", artifact}` | finalize 响应（成功时出现一次，先于 run_end） |
| `run_end` | `{type:"run_end", runId, status: "completed"\|"cancelled"\|"failed", error_code?}` | 恰一个终结帧 |

- `agent_end` stop → 先 finalize 再 `run_end(completed)`；aborted/断开 → cancel 后 `run_end(cancelled)`；错误 → `run_end(failed)`。
- 客户端断开即服务端取消（`session.abort()` + 后端 cancel），工作区前端须处理 mid-stream 断开。
