# 19-01 Truth layer & API honesty

## Objective

Make relationship and clue **projection contracts honest** so UI can differentiate truth tiers without a full KG retrain.

## Steps

### Task 1: Relationship edge honesty
- Files: `backend/app/schemas/relationship.py`, `backend/app/services/relationships/query.py`, FE `api.ts` types if needed
- Add optional `edge_kind` (`accepted_observation` | `provisional_cooccurrence`) and/or stop writing ally/enemy for pure co-occur; use `cooccur`/`unknown` or `suggested_type` only
- When folded accepted non-empty: default return accepted only; `include_provisional=true` may add co-occur layer
- When accepted empty: provisional allowed but must not fake high-confidence fiction types as primary labels
- timeline_kg_backfill: document/seed_only default or mark seed metadata; do not encourage silent pollution

### Task 2: Clue title & span fields
- Files: `clues/worker.py`, `schemas/clue.py`, `clues/query.py`, `clue-api.ts`
- Title: short Chinese-friendly hypothesis (rule-based truncate/cleanup of rationale first line OR "伏笔·第N章" + short stem) — **never** raw cue_unit.text[:80] as sole product title
- Store cue excerpt separately if needed in package_snapshot
- ClueVisibleItem: add optional `first_cue_chapter`, `payoff_chapter` (null if spoiler-hidden), `summary` short line

### Task 3: Tests
- Unit tests for provisional edge_kind / no fake ally default when cooccur-only
- Unit tests for clue title not equal raw long excerpt
- Test, Fix, and Confirm

## Must-Haves

- API consumers can tell accepted vs provisional
- Clue list can show plant/payoff without full detail fetch when safe
- Existing spoiler rules preserved
